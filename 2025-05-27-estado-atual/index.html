O que foi fechado

Tres ajustes pequenos no contrato, mas importantes para seguranca e leitura do PR.

1. escopo de dados

Sem fallback SP quando falta escopo vivo.

Permissoes radar-* liberam a view ou endpoint. A visibilidade dos pontos vem dos filtros vivos de pontos-menu.

Se o usuario nao-global tem Radar mas nao tem escopo vivo, os endpoints autorizados retornam payload vazio, nao dados de SP.

2. mapa

Map-only nao chama dashboard.

O Blade entrega ao radar-app apenas as rotas permitidas para o usuario autenticado.

Quem tem radar-mapa sem radar-dashboard carrega filter options e mapa sem emitir request para dashboard.

3. JSON publico

IDs internos sairam do dashboard.

establishment_ids e excluded_establishment_ids continuam no contexto privado de query/cache.

O JSON publico do dashboard mostra apenas metadados seguros de escopo.

Como testar o comportamento

Exemplos praticos para revisar a mudanca sem precisar inferir a regra pelo diff.

usuario map-only

Fluxo esperado

  • GET /radar/map retorna 200.
  • GET /radar/data/filter-options retorna 200.
  • GET /radar/data/map?limit=1 retorna 200.
  • GET /radar/data/dashboard retorna 403.
  • O HTML da pagina nao inclui a rota de dashboard no payload do radar-app.
usuario Radar sem pontos-menu

Fluxo esperado

  • Endpoints Radar autorizados continuam retornando 200.
  • Listagem, dashboard, mapa e filtros retornam payloads vazios.
  • Nao ha fallback para active_concession=sp.
  • Se faltar permissao do endpoint, a resposta continua sendo 403.
