O drama Vue 2 vs Vue 3

Esse foi o ponto mais sensivel: a preocupacao com cleanup era boa; a premissa da versao estava errada.

Por que o comentario estava equivocado

O projeto usa Vue 3: `package.json` traz `vue ^3.2.36`, `vuex ^4.1.0`, `vue-loader ^17.0.1`, e o bootstrap usa `createApp`. Portanto `beforeUnmount`, `mounted` e `unmounted` sao APIs corretas aqui.

Por que ainda virou fix

A versao estava certa no codigo, mas William levantou riscos reais de cleanup. O patch fortaleceu overflow, timers, observers, CancelToken, sequence guard e listeners delegados.

906ba7945 - harden frontend request cleanup

Ponto de atenção

Não é um bug crítico: é uma diferença entre o que foi prometido na resposta do PR e o que ainda aparece no código.

Atenção: a resposta sobre ES6 ficou ampla demais.

Em um dos comentários, a resposta diz que os `var` foram trocados por `const/let`. Isso é verdade para o store module e para os trechos principais alterados, mas ainda existem `var` em componentes Radar legados. O risco aqui não é funcional; é William ler a resposta como "zeramos todos os var do Radar" e encontrar exemplos restantes.

Como blindar

Não vender como bloqueio. A forma mais limpa é ajustar a frase para "store module e trechos alterados" ou fazer um commit pequeno só para padronizar os `var` restantes nos componentes Radar tocados pelo review.
